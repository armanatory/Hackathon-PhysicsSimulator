# Allsolve liquid-grating integration findings

Recorded with SDK 0.5.2 on 2026-10-03. Raw evidence stays in the saved job folders. These findings do not establish an experimental sensor.

1. A fast-start 3-core / 10 GB simulation must have a runtime limit no greater than 15 minutes. The builder now uses 15 minutes for search/dense jobs and a separate 4-core / 64 GB node for fine verification.
2. A running simulation can return HTTP 404 for its output database before publication. A successful child can also precede complete scalar publication in the sweep database. The collector waits for complete valid outputs, and re-reads invalid partial snapshots at parent completion. Earlier collections remain archived.
3. `SimulationOutputData.to_dict(sweep_index)` indexes the sorted list of available rows. Its index is not necessarily the row's submitted `job_index` during sparse publication. The collector uses list position for decoding, and the saved job index plus returned input/geometry metadata for point identity. A regression reproduces this using the installed SDK's implementation.
4. One physical mesh in the original search had a geometry different from its override metadata. Job `aed28d07312946c39a0de7e049f4c7b7`, batch 2 mesh file `xWYmZlQqaA6hAVmm8N`, index 0 declares period 540.408914 nm and height 199.798994 nm. Its node extents instead have period 452.664278 nm and height 179.233639 nm, matching another candidate. This accounts for the server's empty entrance/liquid/xmax selectors. A cache or file-association error is a hypothesis, not an established internal cause. The wrong bytes and SHA256 are retained in that job's `diagnostics/mesh_provenance/evidence.json`.
5. Every mesh is now downloaded and checked against the requested outer dimensions and internal interface coordinates, to 0.001 nm, before its solve can be accepted. The new project's first 14 files passed this check. Fresh successful geometry is not evidence that the original wrong file was fixed by changing the region-selection tolerance.
6. Some otherwise successful cloud solves produce poor energy balance or cross-polarized power in this invariant TE model. Those points are rejected. In particular, the first sampled leader failed the dense-mesh readout checks and was excluded from final selection. The retained periodic-slab investigation also observed null-pivot warnings; redundant constraints are a possible explanation requiring solver-level diagnosis.

The frontend shows actual job counts, valid spectra, selected dimensions, and verification metrics. Neither RCWA values nor synthetic spectra are used as optimization results.
