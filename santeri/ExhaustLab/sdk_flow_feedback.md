# Allsolve airflow usability findings

Observed with installed Python SDK 0.5.2 on 2026-10-03. All credentials stayed server-side. These findings concern one bounded 3D straight-channel case; the underlying helper failure has not been diagnosed.

The reproducible fixture is a 60 mm long, 20 mm wide rectangular gas domain with 4/6/8 mm plate gaps, 0.2 L/min entered flow, density 1.2 kg/m³ and viscosity 1.81e-5 Pa·s. It uses a developed rectangular-duct inlet velocity, no-slip side/plate walls, and zero outlet gauge pressure. Physics/domain IDs and region selections were checked. Velocity order 2 and pressure order 1 were confirmed by a read-only API inspection and in the generated script.

1. **Field-order updates require awkward cache handling.** Consecutive `set_field_interpolation_order()` calls can discard the first unsaved change. After `save()`, the cached physics fields lose their `definition` metadata and `flow.fields` raises `ValueError: Physics field has no definition`. Cache both IDs before updating, save each update, and reacquire physics through the project API. The raw payload omits unset definitions; this observation does not imply lost server-side definitions.
2. **A successful job did not establish a valid flow solution.** The generated `predefinednavierstokes` path completed, but the exported 4 mm flow decayed away from the imposed inlet: sampled inlet flux was about 3.31e-6 m³/s while outlet flux was about 3.90e-18 m³/s. Internal pressure drop was effectively zero instead of the expected 0.03883 Pa. Volume and boundary values looked correct. The project team also observed failure using the predefined Stokes helper. Root cause remains unknown; it could involve helper/runtime behavior or its generated configuration. A native `SUCCESS` status therefore needs separate physical checks.
3. **Explicit stationary incompressible weak form recovered the benchmark.** A custom formulation using `mu*grad(dof(V)):grad(tf(V)) - dof(p)*div(tf(V)) + div(dof(V))*tf(p)` passed the pressure, profile, and conservation checks. This is a Stokes formulation. It is appropriate for the developed straight-channel benchmark because the advective term is zero for an axial velocity independent of x. It does not justify using this formulation for arbitrary bends, baffles, developing high-Re flow, or full hot exhaust.
4. **Export and validation interfaces are useful once verified.** Genuine Allsolve point interpolation exports provided velocity, pressure, potential and electric field. Direct finite-element inlet/outlet flux and mean-pressure integrals were added to later runs. At 6 mm, direct FE flux mismatch was about 0.00934%, developed pressure error about 0.00305%, and velocity-profile L2 error about 0.0742%. Electrostatic uniform-field results agreed at machine precision. Local validators include immutable source-file hashes so a successful old validation cannot authorize newly replaced fields.

Suggested SDK improvements: preserve field metadata and pending updates; expose an explicit stationary laminar/Stokes example with conservation outputs; record actual nonlinear and mass-balance convergence alongside job status; document VTKHDF output and automatic decompression consistently. Preserve the failed helper simulation when opening a support report, along with generated script, job IDs, material properties, BCs, and the measured loss of outlet flux.

Local evidence: `cloud_study.py`, `research_flow.md`, `runs/gap4/generated_flow/main.py`, each case's `state.json`, point exports and `validation.json`. Corrected 6/8 mm cases include the `direct_fe` validation group. The independent 6 mm mesh comparison in `runs/convergence_fields.json` passed: reducing the maximum element size from 1.5 mm to 1.0 mm changed fitted pressure drop by 0.00350%, common-grid velocity by 0.0783% in relative L2, and FE outlet flow by 0.0270%. The fine velocity profile had 0.0393% relative L2 error against the finite Fourier reference. This supports this straight-channel benchmark, not a general error bound for other exhaust geometry.

The later independent fine meshes for 4 and 8 mm also passed every flow/electrostatic gate. `runs/all_field_convergence.json` records all three comparisons and current source-file hashes. Fitted-pressure changes for 4/6/8 mm were 0.0163%/0.00350%/0.00652%; common-grid velocity L2 changes were 0.0759%/0.0783%/0.0554%. Fine-mesh velocity-profile errors against the analytic reference were 0.0406%/0.0393%/0.0229%. All fine cases use the explicit stationary weak-form recovery, with the same scope limitation.

## Additional observed SDK friction

- The expression parser rejected `cosh` in the developed inlet with `Unknown function cosh`. The equivalent stable exponential ratio works: `cosh(a*(z-W/2))/cosh(a*W/2) = (exp(a*(z-W))+exp(-a*z))/(1+exp(-a*W))` for the channel interval. This also avoids overflowing exponential intermediates.
- Pointwise cloud interpolation of 3,825 locations took roughly 170 seconds after the solve. Collective batched `qs.allinterpolate` reduced the observed extraction phase to about a second for the same point count. The helper accepts scalar components and flattened xyz triples; sample components separately and restore vector order explicitly.
- A 27,489-point refined grid exceeded the value-output IPC message limit: `message is too large: 1816020 > 1048576`. Exporting named arrays in chunks of 10,000 scalar values and concatenating them in numeric order fixed the failure. A configurable documented bulk numerical export interface would avoid this trial-and-error.
- `save_generated_scripts` gives helper modules but not the full main simulation or custom-section composition. The read-only raw API can retrieve the generated main; the case also retains explicit custom code in `cloud_study.py`. Job/provenance manifests should carry the final compiled script and runtime version directly.

Final source provenance is in `runs/final_manifest.json`. The observed solver banner is `Quanscient Allsolve 484 int64/float64`; the SDK is 0.5.2. All simulations use one solver rank. Geometry/meshing and final solves were cloud runs, while trajectory integration and refinement comparisons ran locally. No support report or message has been sent externally.
