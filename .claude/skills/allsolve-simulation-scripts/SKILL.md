# Allsolve simulation scripts

Most workflows use SDK helpers (`create_simulation_*`, physics interactions, outputs) and **do not** need manual script edits. Load this skill only when adding custom script sections or fixing script failures.

**Custom scripts run on the Allsolve server** when `sim.run()` executes. They cannot be run or stepped through locally — there is no debugger attach, no local simulation runtime. Write and validate syntax locally; errors surface only in **cloud job logs** after a run.

**Docs:** [Simulation script](https://allsolve.quanscient.com/documentation/using-allsolve/simulations/script) · [Script API](https://allsolve.quanscient.com/documentation/reference/api)

## Attach custom code

```python
sim.set_scripts([
    allsolve.Script(
        name="init_temp.py",
        section_name=allsolve.CustomSection.AFTER_FIELDS_CREATED,
        content="fld.T.setvalue(reg.all, expr.room_temp)",
    )
])
```

Provide code via `content` (inline string) or `filepath` (`.py` on disk, read at `set_scripts` time). Set `is_main=True` only to replace the entire generated main script.

Common injection points (`CustomSection`):

| Section | Typical use |
| ------- | ----------- |
| `AFTER_FIELDS_CREATED` | Initial field values, custom fields |
| `AFTER_CONSTRAINTS_CREATED` | Extra boundary conditions |
| `AFTER_FIELD_INITS` | Override generated initial conditions |
| `AFTER_FORMULATIONS_CREATED` | Modify weak form before solve |
| `BEFORE_TRANSIENT_SOLVE` | Per-timestep updates (transient only) |
| `AFTER_ALL` | Post-processing |

See `help(allsolve.CustomSection)` or SDK reference for the full list and analysis-type-specific sections.

## Solver environment vs SDK script

Custom scripts run **on the cloud solver**, not in your local SDK file. Python names from the SDK script (constants, function args, imports) are **not** in scope.

Autogenerated helper modules are injected at runtime:

| Symbol | Module | Use |
| ------ | ------ | --- |
| `expr.<name>` | `expressions` | Project variables and functions |
| `par.<name>()` | `parameters` | Material / interaction parameters per region |
| `reg.<name>` | `regions` | Region IDs |
| `fld.<name>` | fields namespace | Finite-element fields |
| `qs` | `quanscient` | Script API (`import quanscient as qs`) |

```python
# Correct — project variable
content="fld.T.setvalue(reg.all, expr.room_temp)"

# Correct — runtime override of a project variable
content="expr.room_temp = qs.expression(273.15); fld.T.setvalue(reg.all, expr.room_temp)"

# Also fine — bake a value when building Script content at SDK time
content=f"fld.T.setvalue(reg.all, {293.15})"

# Wrong — bare name not in solver namespace (NameError)
content="fld.T.setvalue(reg.all, room_temp)"
```

Project variables must be defined first: `project.create_variables([("room_temp", "293.15", ...), ...])`.

## Inspect generated scripts (reference only)

Fetch server-generated helpers to see exact `expr.*` / `par.*` names and aid local editing — **these files are not executed locally**:

```python
sim.save_generated_scripts("./generated_scripts/")
# writes utils.py, regions.py, expressions.py, parameters.py, materials.py, ...
```

Use with `quanscient-stubs` for IDE autocomplete while writing script strings. Refresh after changing project variables or regions.

## Typed stubs (Script API)

When editing simulation scripts manually, use the typed stubs for `qs.*` functions, fields, parameters, and enums:

- GitHub: [quanscient-stubs/__init__.pyi](https://github.com/Quanscient-Public/allsolve-sdk-python/blob/main/src/quanscient-stubs/__init__.pyi)
- Installed locally as `quanscient-stubs` with the `allsolve` package (e.g. `.venv/lib/python3.14/site-packages/quanscient-stubs/__init__.pyi`)

## Troubleshooting (logs only)

There is no interactive debugging. Workflow:

1. Edit script content in the SDK (or GUI script editor).
2. Run `sim.run(print_logs=True)`.
3. Read the job log — tracebacks, `NameError`, and syntax errors appear there before results upload.
4. Fix and re-run.

To inspect values on the server, use `print(...)` in the custom script section — output appears in the simulation logs under Results.

After changing project variables or regions, regenerated helpers update on the next run; call `save_generated_scripts` again if you need an updated local reference copy.

## Gotchas

### Harmonics and field access

- **Harmonic numbering:** 1=DC, 2=cos(wt), 3=sin(wt), 4=cos(2wt), 5=sin(2wt), …
- **For transient fields:** do NOT pass harmonic indices to `qs.field()`.
- **Gradient of harmonics:** always `qs.harm(n, qs.compx(qs.grad(field)), N)`, never `qs.grad(qs.harm(...))`.
- **`qs.norm()` for transient:** `qs.norm(fld.u)`. For harmonic: `qs.norm([2,3], fld.u, 3)`.
- **`qs.field("x")` returns metres**, not internal mm.
- **`qs.field("y")` for y-coordinate** — use `qs.field("y")`, not `qs.compy(qs.field("x"))`.

### Data structures

- **`densemat` is not a Python list** — use `dm.getvalue(i, 0)` to read elements.
- **`vec.setdata(reg, field)` reads field INTO vec**, not the other way.
- **`qs.evaluate()` may return list or scalar** — always unwrap: `float(v[0]) if isinstance(v, (list, tuple)) else float(v)`.

### Injection points

- **`AFTER_SOLVE` does NOT fire when `DisableableSection.SOLVE` is disabled** — all injection points within and after the solve section are skipped. Place custom loop code in `AFTER_FORMULATIONS_CREATED` instead.
- **`BEFORE_TRANSIENT_SOLVE` indentation is unreliable** — recommended alternative: disable SOLVE and write the complete time loop in `AFTER_FORMULATIONS_CREATED`.
- **`AFTER_SOLVE` silently does nothing for typed harmonic sims.** To run post-solve code, disable SOLVE and do `form.allsolve(...)` + readout in `AFTER_FORMULATIONS_CREATED`.
- **`qs.evaluate` cannot return a multiharmonic value** — extract a single harmonic first: `qs.evaluate(qs.harm(2, port.port.V))`.

### Custom time loops

- **When modifying the solve loop, copy the project's own generated loop** — fetch via `api.get_generated_scripts(...)` → `g.simulation.code`. Disable SOLVE and re-inject an edited copy at `AFTER_FORMULATIONS_CREATED`.
- **`qs.setoutputvalue(name, val, freq)` for frequency-domain array outputs** — after the time loop, call `setoutputvalue` in a loop with the frequency as the "time" coordinate.
- **Per-step Dirichlet update works** — re-call `fld.p.setconstraint(...)` before each `timestepper.allnext(...)`.

### Predefined waves and PML

- **`predefinedacousticwave` no-PML overload:** use the 5-arg form, do NOT pass `None` as PML arg.
- **`numpy` and `scipy` are available** inside custom script sections. `quanscient` / `qs` is the solver module and is NOT importable locally.

### Advanced

- **`genalpha` is consistent-mass with no lumping knob; its default IS Newmark.** There is no switch for lumped (diagonal) mass.
- **`genalpha` with moving-Dirichlet coupling adds large reflection** (~62.7% vs ~3.2% with custom lumped-mass Newmark). Do NOT use `genalpha` for Dirichlet interface regions.
- **`formulation.b()` returns the NEGATED nodal load** — negate `b()` to get internal stiffness force.
- **`vec` has no coordinate info** — build a DOF-to-coordinate map by setting the field to coordinates, gathering into a vec, and reading all entries.
- **Extract operator matrix column-by-column** — set field to each basis function via `qs.grid` indicator, then read `-form.b()` = column j.
